1. 핵심 요약 및 2026 시장 지표

기준 시점: 2026년 11월 25일 (OGC·Apache·OSGeo·주요 벤더 공식 발표 기준)

2026년 GIS와 지도 플랫폼 업계는 세 가지 축으로 재편되고 있습니다. 첫째, GeoParquet 2.0과 Apache Iceberg 1.12가 공간 데이터 타입을 범용 데이터 레이크하우스 표준으로 편입시켰고, 둘째, AI 모델이 현실 세계를 이해하도록 돕는 MCP(Model Context Protocol) 지도 도구와 지구관측 임베딩 파운데이션 모델이 상용화되었으며, 셋째, QGIS 4.0의 Qt6 세대교체와 서버리스 Cloud-Native Geospatial 스택이 FOSS4G 생태계를 주도하고 있습니다.

16배 ↓ AlphaEarth 임베딩 용량 전 지구 10m 격자 요약 시 기존 대비 저장 공간 절감

한눈에 보는 2026년 지형 변화

과거 GIS가 전용 파일(Shapefile)과 무거운 서버(WMS/WFS) 중심이었다면, 2026년에는 Parquet·Iceberg·DuckDB·PMTiles 기반의 객체 스토리지 네이티브 파이프라인과 AI 에이전트용 MCP·GERS ID·3D Gaussian Splatting(glTF/3D Tiles 2.0)이 표준으로 수렴하고 있습니다.

2. 2026년 신규 표준화 기술 동향 (승인 완료 vs 진행 중)

공식 발행·승인된 표준과 비준·초안 단계 기술을 구분해 정리했습니다.

2026년 표준화의 최대 이정표는 공간 타입이 별도 GIS 포맷을 넘어 메인스트림 데이터 포맷(Parquet, Iceberg, DuckDB)의 일급 시민으로 들어온 것과, GeoJSON의 한계를 보완한 OGC JSON-FG·포인트 클라우드 압축 LAZ 1.4·위성영상 처리 API openEO의 공식 승인입니다. 한편 3D Tiles 2.0과 glTF 3D Gaussian Splatting, GeoZarr는 비준 및 초안 단계가 진행 중입니다.

  • GeoParquet 2.0 핵심 변화: 2025년 3월 Apache Parquet 2.11에 도입된 GEOMETRY·GEOGRAPHY 논리 타입을 토대로 2026년 11월 24일 정식 출시되었습니다. 1.x의 추가 bbox 컬럼 없이도 Row Group 공간 통계로 빠른 필터링이 가능하며, 일반 Parquet 엔진도 공간 컬럼을 직접 인식합니다. (https://cloudnativegeo.org/blog/2026/11/geoparquet-2-0-released/)

3. AI를 활용한 GIS·지도 신기술

파운데이션 임베딩 모델, 에이전트용 MCP, 3D 가우시안 스플래팅이 핵심 축입니다.

지구관측 AI

파운데이션 모델

위성·공간 임베딩 파운데이션 모델 (AlphaEarth · Earth AI · Prithvi · Clay)

Google DeepMind의 AlphaEarth Foundations는 광학·레이더·LiDAR·기후 데이터를 결합해 전 지구 육지·연안을 10m×10m 격자 임베딩으로 압축(저장 용량 16배 절감, 평균 오차 24% 감소)해 Earth Engine에 공개했습니다. Google Earth AI는 Gemini 공간 추론 에이전트로 다중 모델을 오케스트레이션하며, 오픈 진영에서는 NASA/IBM의 Prithvi-EO-2.0과 Development Seed의 Clay가 활발히 쓰입니다.

에이전트 × MCP

MCP 표준화

AI 에이전트의 '위치 맹점(Blind Spot)'을 해결하는 지도 MCP 서버

Google은 Maps Grounding Lite를 Maps Experience agent tools로 정비해 호스팅 MCP(mapstools.googleapis.com/mcp)와 REST API를 제공합니다. Mapbox는 2026년 9월 BUILD에서 33개 도구 오픈소스 MCP 서버, Notion·Figma MCP 커넥터, Maps/Navigation SDK용 Agent Toolkit을 공개했습니다. 학계와 ISO/TC 211에서도 OGC API를 MCP 도구로 매핑하는 GeoMCP·OpenGA 프레임워크가 논의되고 있습니다.

실시간 예측·검색

자연어 공간 검색, AI 교통 예측(Traffic 2.0), 대화형 공간 분석 에이전트

Mapbox는 45,000+ 앱의 실시간 텔레메트리를 학습해 2.5시간 앞 교통을 예측하고 98% ETA 정확도를 내는 Traffic 2.0과 대화형 Search Box NLQ를 선보였습니다. Foursquare는 2026년 2월 자연어로 공간 분석을 수행하는 FSQ Spatial Agent를 출시했습니다.

3D 리얼리티 캡처

3D Gaussian Splatting의 상용 GIS 분석 편입

단순 3D 웹 뷰어를 넘어 분석 단계로 진입했습니다. Esri ArcGIS Enterprise 12.2 Scene Viewer는 가우시안 스플랫의 단면·가시선·고도 프로파일 분석을 지원하고, ArcGIS Pro 3.8은 스플랫 데이터 내부의 3D 객체를 AI로 탐지해 공간에 배치할 수 있습니다. XR Viewer에는 음성 AI 어시스턴트(베타)가 추가되었습니다.

4. FOSS4G 진영의 가장 활발한 움직임

FOSS4G 2025 오클랜드(2025.11)와 FOSS4G 2026 히로시마(2026.08~09)를 관통하는 핵심 흐름

FOSS4G 진영은 2025년 11월 뉴질랜드 오클랜드 대회에 이어 2026년 8월 30일~9월 5일 일본 히로시마에서 글로벌 콘퍼런스(FOSS4G 2026 Hiroshima)를 개최했습니다. 2026년 커뮤니티 에너지는 크게 세 가지, 즉 QGIS 4.x 세대교체, GDAL·DuckDB·GeoParquet·PMTiles 기반 서버리스 스택, 그리고 브라우저·웹 지도 엔진(MapLibre, OpenLayers, Leaflet 2.0)의 고도화에 집중되었습니다.

객체 스토리지 포맷 GeoParquet 2.0 · COG · GeoZarr

렌더링·추론

클라이언트·에이전트 QGIS 4.x · MapLibre 5.x · AI 에이전트
  • QGIS 4.0 Norrköping (2026.03) → QGIS 4.4.0 (2026.11): 수년간 준비한 Qt5→Qt6 전면 마이그레이션이 2026년 3월 결실을 맺으며 High-DPI 네이티브 렌더링, 멀티스크린 지원, 100개 이상의 신기능을 탑재했습니다. 3.40 LTR 유지보수와 병행하며 플러그인 생태계의 Qt6 전환이 2026년 최대 커뮤니티 과제였습니다. (https://blog.qgis.org/2026/03/09/qgis-4.0-norrk%C3%B6ping-is-released/)
  • GDAL 3.11~3.13 & DuckDB 1.5의 결합: GDAL 3.11에서 차세대 통합 gdal CLI와 DuckDB ADBC 드라이버가 도입되었고, 3.12에서 Parquet 네이티브 지오메트리 지원, 3.13에서 벡터 CLI 연산(dissolve, hulls 등)이 확장되었습니다. DuckDB는 1.5.0(2026.03)에서 GEOMETRY를 코어 타입으로 내장했고, vgi-mvt 등으로 DuckDB 테이블을 곧바로 PMTiles로 내보내는 워크플로가 확산 중입니다.
  • PostGIS 3.6.2 & 웹 지도 엔진: PostGIS 3.6.2(2026.02)는 PostgreSQL 18(베타) 호환과 MVT 확장, SFCGAL 2.2 3D, 구면 연산용 pgSphere를 지원합니다. 웹에서는 Mapbox 라이선스 제한의 표준 대안인 MapLibre GL JS 5.x가 v6을 준비 중이며, FOSS4G 2026에서는 DuckDB + MapLibre + AI 조합의 브라우저 네이티브 분석 시각화와 Leaflet 2.0 공식 소식이 주목받았습니다.
  • GeoServer Cloud · pygeoapi · Portolan: 기존 모놀리식 GeoServer를 넘어 클라우드 네이티브 GeoServer Cloud 3.0(GeoParquet 2.0 읽기 지원), 경량 OGC API 구현체 pygeoapi, 그리고 GeoParquet·PMTiles·COG·STAC 발행을 묶는 서버리스 SDI 프로젝트 Portolan이 부상하고 있습니다.

5. 산업계 · Overture Maps · 국내 플랫폼 동향

오픈 데이터(Overture 2026-11-18)와 국내 공간정보·빅테크 움직임

Overture Maps Foundation(AWS·Meta·Microsoft·TomTom 주도, Esri·Niantic·OGC 등 참여)은 2026년 11월 18일 2026-11-18.0 데이터와 Pydantic 기반 Python SDK를 포함한 v2.0.0 스키마를 공개했습니다. 건물 데이터만 25.44억 개, 장소(Places) 9,030만 개, 주소 4.75억 개 규모이며, 영구 식별자 GERS를 통해 서로 다른 지도·AI 파이프라인 간 현실 객체 연결의 공용 키 역할을 하고 있습니다. 출처: https://docs.overturemaps.org/blog/2026/11/18/release-notes/

7. 실무·제품 관점 시사점

신규 GIS·위치 기반 제품 설계 시 고려해야 할 아키텍처 선택지

  1. 1) 저장·분석 포맷은 GeoParquet 2.0 + DuckDB 1.5 + PMTiles 조합 검토

    대규모 공간 분석을 위해 무거운 전용 GIS 서버를 먼저 세우기보다, 객체 스토리지(S3) 위 GeoParquet 2.0(또는 호환성이 필요하면 1.1)과 DuckDB, 웹 타일 서빙용 PMTiles + MapLibre 조합이 비용과 속도 면에서 압도적으로 유리합니다.

  2. 2) AI 에이전트 연동은 MCP 서버 및 GERS 기반 그라운딩을 기본 설계로

    지도 UI와 별도로 LLM/에이전트가 공간 맥락을 조회할 수 있도록 Google Maps Experience agent tools(MCP), Mapbox MCP 서버, 또는 자체 OGC API 래퍼 MCP를 설계하고, 다중 데이터 결합 시 Overture GERS ID를 연결 키로 활용하면 유지보수성이 크게 높아집니다.

  3. 3) 3D·디지털트윈은 glTF + SPZ 및 3D Tiles 2.0 호환성 확보

    현장 스캔·드론 데이터를 3D Gaussian Splatting으로 구축할 때는 독자 PLY 파이프라인에 갇히지 않도록 Khronos KHR_gaussian_splatting / SPZ(MIT)와 OGC 3D Tiles 2.0 흐름에 맞추는 것이 장기 호환에 유리합니다.

  4. 4) 데스크톱·ETL은 QGIS 4.x 및 GDAL 3.12+ 전환 일정 반영

    QGIS 4.0(Qt6) 전환에 따라 사내 커스텀 파이썬 플러그인의 Qt6 호환성 점검이 필요하며(안정 운영 시 3.40 LTR과 병행 검증), ETL 스크립트는 새로운 통합 gdal CLI와 Arrow/Parquet 파이프라인으로 단순화할 수 있습니다.

  • S3 + GeoParquet + PMTiles + MapLibre 조합으로 서버리스·무과금에 가까운 타일 서빙 가능
  • Overture Maps GERS·오픈EO·STAC·OGC API 표준으로 특정 상용 벤더 락인 최소화
  • DuckDB 1.5 코어 GEOMETRY와 Iceberg 1.12로 비GIS 데이터 엔지니어링 팀과 협업 장벽 해소
